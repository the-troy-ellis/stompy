## Summary

Two or three sentences: what the player gets and why it is worth building.

## Player experience

What it looks, sounds and feels like from the cockpit. Desktop and touch both.

## Design

The rules. Numbers in a table. Edge cases. What happens in the arena.

## Code touchpoints

Files and functions this changes or adds, with a sentence each. Data shape
changes written out.

## Acceptance criteria

A numbered list. Each item is demonstrable by a test, a screenshot or a
reviewer step.

## Tests

Which unit tests, what they assert. Which playtest steps are new.

## Performance

an acceptable answer when true.

proceed.
